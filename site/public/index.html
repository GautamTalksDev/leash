Three rules,
enforced outside the model.

    

      
01
The agent never holds a real key
Keys live in a vault where every secret has its own AES-256 key, wrapped by a master key. Agents get lsh_ proxy tokens: scoped, expiring, revocable. Leak one and you leaked nothing.

      
02
Irreversible means held
LEASH knows which calls on each API can't be undone, and holds them until a human approves with a passkey. An approval covers that exact request, once, for ten minutes.

      
03
Everything is on the record
Every call, hold, approval and denial goes into an append-only log where each entry commits to the one before. Edit a row and the chain breaks.

Built like it guards production. Because it does.

    
    
      
  • Passkeys only. No passwords to phish.
    • 
      
  • A CLI session can never approve a hold: an agent on your laptop can read the CLI's files.
    • 
      
  • Envelope encryption, AAD-bound rows, keys never logged, never returned by any API.
    • 
      
  • Strict CSP with Trusted Types, HSTS preload, SameSite=Strict, CSRF headers, no CORS.
    • 
      
  • Rate limits per token and per IP (IPv6 by /64). No redirects followed upstream.
    • 
      
  • Shaped after the IETF draft "Credential Broker for Agents" (CB4A).
